== Why Naive AI Workflows Create Mess — and What Changed Here

When repositories undergo rapid stack migrations (here: legacy ReScript/TEA and A2ML -> Vue 3 SFCs, Bun, DEED v1.2.0, K9 v1.0.0, and Zig/Idris2 FFI), unconstrained AI assistance typically leaves **sedimentary layers**:

* **Migration Ghosts & Unadapted Containers** — Documentation (`TEA-Pattern.adoc`, `CITATIONS.adoc`, `ROADMAP.adoc`, `.gitlab-ci.yml`, `Containerfile`, `CONTRIBUTING.md`, `GOVERNANCE.adoc`, `Befunge93.adoc`) continued describing ReScript compilers, Deno-only pipelines, MIT licenses, missing `--surface-*` CSS variables, and single-stage containers lacking `_build/ffi/libbefunge93_vault_cracker.so` or `dist/app.js`.
* **Disconnected "Museum Pieces"** — `src/engine/befunge93.js` contained a complete, working Befunge-93 VM (`stepVm`), yet production gameplay stepped through a **hardcoded 18-element array literal (`WALK_TRACE`)** while `stepVm` was only called by unit tests. Similarly, `ffi/zig/src/main.zig` compiled a single-grid native Zig VM whose output was **deleted immediately after `zig build`** (`rm -rf zig-out`) and padded with five generic template C-ABI stubs (`process`, `process_array`, `get_string`, `register_callback`).
* **Framework, Accessibility & CSP Shortcuts** — `useVaultGame.js` wrapped a non-reactive `let timerHandle` inside `computed(() => timerHandle !== null)`, `PlayfieldGrid.vue` placed `role="gridcell"` directly under `role="grid"` without `role="row"` wrappers, `TelemetryPanel.vue` used 14 inline `style="..."` blocks referencing undefined CSS custom properties (`--surface-2`, `--border-subtle`), and `server.js` weakened CSP with `style-src 'unsafe-inline'`.

=== Guardrails That Prevented Entropy Across All Eight Stages

1. **Pre-Cleanup Saturation (`S0`)** — Before modifying a single production file, we expanded unit tests across all 26 Befunge-93 opcodes and underflow/bounds edges, TEA state transitions, torus keyboard wrap-around in `happy-dom`, Marid timeout/abort/204/non-JSON/CRLF wire edges, `4,200` generative property cases (`277,192` `expect()` calls), and 7 JS + Zig benchmarks.
2. **Append-Only Stage Measurement (`S0`..`S7`)** — Every stage was validated by an automated harness (`/tmp/measure_step.py` -> `benches/baseline.json`) running `just check` (16 parallel gates), `deno task test`, `pnpm run test`, `Bun.build`, `benches/befunge93.bench.js`, `zig build bench`, and AST smell/export scanners.
3. **Contractile Integrity (`must.k9.ncl` Pledge Honoured)** — Emitting Zig FFI artifacts into gitignored `_build/ffi/` kept `ffi/zig/` 100% pure source so every `must.k9.ncl` probe remained untouched and unweakened.

== Bonus Defect Spotlights: Why Saturation & Per-Step Rebenching Pay Off

=== Spotlight 1 (`S0` Saturation -> `P-15` Stream Double-Read Bug)

While writing the `S0` saturation test for `MaridWireClient` against a simulated reverse proxy returning plain-text `502 Bad Gateway Text` (`Content-Type: text/plain`), `S0` immediately uncovered **`P-15`** in `src/marid/marid-wire-client.js`:

[source,javascript]
----
// BEFORE (latent stream typestate bug):
try {
  problem = await res.json(); // <-- consumes ReadableStream body!
} catch {
  const fallbackText = await res.text().catch(() => ""); // <-- ALWAYS throws ("Body already used") -> ""
  problem = { status: res.status, title: res.statusText, detail: fallbackText || `HTTP ${res.status}` };
}

// AFTER (S2 single-read fix):
const rawText = await res.text();
try {
  problem = rawText.length > 0 ? JSON.parse(rawText) : {};
} catch {
  problem = { status: res.status, title: res.statusText, detail: rawText.trim() || `HTTP ${res.status}` };
}
----

=== Spotlight 2 (`S7` Rebenching -> `X-04` Zig Debug-Linkage & Per-POST Allocation Catch)

On the first `S7` measurement run after expanding the Zig VM to 26 opcodes with a `[2048]i64` stack (`16 KB`), our automated harness flagged two immediate latency shifts even though all `281,044` test assertions passed:

1. `marid.postAndSseFrame` rose from `13.4 µs` to `29.8 µs` because `POST /api/vault/runs` allocated a fresh `12 KB` `Uint8Array` and re-parsed the 10x10 grid on every request. Reusing preallocated scratch buffers in `native-oracle.js` and caching immutable level verification in `local-trial-backend.js` restored `p50` to **`12.6 µs`** (`55,225 ops/s`).
2. `zigBenchNsPerOp` rose from `1,689 ns` to `2,982 ns` — proportional to the local stack buffer size! Inspecting `ffi/zig/build.zig` revealed why: `bench_mod` set `.optimize = .ReleaseFast`, **but linked `lib_static`, which defaulted to `Debug` mode** (`0xaa` poison-filling the entire stack array on every call). Linking `bench_mod` against a dedicated `.ReleaseFast` `lib_bench_static` dropped native C-ABI execution to **`475 ns/op` (`2.10 million` full 10x10 vault executions/sec)**.
