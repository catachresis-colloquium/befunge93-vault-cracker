= Changelog

All notable changes to `befunge93-vault-cracker` are documented in this file.

== [0.4.1] - 2026-10-24

Defect-fix release. `v0.4.0` (PR #83) merged with a red test suite and a Custom Vault Workshop that could not author grids in the browser. Every item below was reproduced against `main` at `8cbb49d` before being fixed.

=== Fixed

* `src/components/WorkshopGrid.vue` — the authoring grid was *imported by nothing*, so the Workshop rendered its controls but no editable playfield: the headline `v0.4.0` feature was unreachable in the browser. Now wired into `WorkshopPanel.vue`.
* `src/components/WorkshopGrid.vue` — the `:aria-label` expression embedded unescaped double quotes inside a double-quoted attribute (`${cell === " " ? ...}`), so the component failed the repository's own `compileVueSfcSource` with `Unexpected token (1:38)`. The defect was invisible precisely because nothing imported the file; switched to single quotes to match `PlayfieldGrid.vue`.
* `src/engine/workshop.js` — `WORKSHOP_GLYPHS` was a 36-glyph opcode-only subset that omitted `g` and `p`, the self-modifying opcodes that both `stepVm` and the Zig C-ABI VM dispatch on, contradicting its own doc comment. It now spans printable ASCII (`0x20..0x7E`, 95 cells), which is what Befunge-93 actually permits: unrecognised glyphs are no-ops, and `p` plus string mode can write arbitrary values to the torus anyway.
* `src/engine/game-state.js` — `EnterWorkshop` cloned the level grid into a state the Workshop's own validator rejected, so *all three shipped levels opened broken* (`vault-alpha`/`torus-wrap` on the decorative `=====`, `VAULT!`, `93-TEA` art; `self-mod-cipher` on `g`). Every level now seeds a valid grid.
* `src/engine/game-state.js` — `SetWorkshopCell`, `SetWorkshopGrid`, and `SetWorkshopMaxSteps` returned `state` unchanged on invalid input, silently discarding every edit. Combined with the two defects above this made the editor completely dead on any shipped level. Rejections now route through `rejectWorkshopMutation`, which preserves the grid and records the reason in `workshop.lastError` and the rolling log.
* `src/components/WorkshopPanel.vue` — surfaces `workshop.lastError` as a `role="alert"` notice using the existing `--vault-err-*` tokens (no inline styles, no `.innerHTML`).
* `src/components/WorkshopGrid.vue` — glyph cycling steps the new curated `WORKSHOP_OPCODE_CYCLE` (35 opcodes including `g`/`p`) rather than every printable cell, and enters the cycle at its start for a non-opcode data glyph instead of advancing from `indexOf === -1`.
* `benches/befunge93.bench.js` — `sfc.compileAllComponents` compiled only 7 of the 9 shipped SFCs, omitting both Workshop components; that coverage gap is what let an unparseable SFC ship. The list now matches `src/**/*.vue`.
* `tests/property/befunge93-properties.test.js` — Property P6 was the only property using unseeded `Math.random()`; it now uses `mulberry32(0xbf93_0009)` like P7-P9. It had been failing *deterministically* on `main` since PR #83 (`69` pass / `1` fail, `405,045` assertions), contradicting that PR's recorded "`70/70` pass, `508,044` assertions".
* `tests/unit/game-state-workshop.test.js` — three tests pinned the silent-rejection defect as expected behaviour (`toBe(before)`) and asserted `glyph: "Z"` was invalid; they now assert that rejections are observable, that the authored grid is preserved, and that printable data glyphs are accepted.
* `.hypatia-ignore` — the CSA003 exemption for `.claude/CLAUDE.md` justified itself by claiming the file "no longer exists in the repository". It is tracked and was adapted to current reality at `S6`. Corrected to the true ground (the file names `.a2ml` only in order to prohibit it) and scoped so that new findings on that live file are triaged rather than assumed stale.
* `tests/contracts/canonical-wrongness-r10.test.js` — comment still read "version 0.2.0" while asserting `0.4.0`.
* `befunge93-vault-cracker.ipkg` — `version = 0.2.0` was stale by three releases; coupled to `0.4.1`.
* `.github/workflows/ci.yml` — the `Vue 3 + Bun System, Game & Benchmark Suite` job provisioned Idris2 (`apt-get install -y idris2`) as its *fourth* step, so once the runner image stopped shipping that package the job aborted at exit `100` **before `bun test` ever ran**. That is precisely how the deterministically failing Property P6 reached `main` in PR #83, with CI reporting the suite as never-run rather than as red. Idris2 provisioning and the `%default total` typecheck now run *last*, after every gate that does not depend on them. The gate stays strict: it still fails the job when the compiler cannot be provisioned, and never skips into green. No `uses:` refs changed, so `actions.lock` (`v0.0.3`) needs no update.

=== Added

=== Known Issues

* **CI has now revealed a JS↔Zig differential VM divergence that had never been tested.**
  With the Idris2 step moved last (see Fixed), `bun test` executed in CI for the
  first time in at least five runs — and with the native Zig oracle *genuinely
  present*, because this job builds `_build/ffi` (the Multi-Runtime Gate jobs do
  not, which is why those stay green). Two differential-oracle tests then failed:
  `Property P9 (differential JS VM vs native Zig C-ABI lockstep on
  workshop-authored random 10x10 grids)`, and the Workshop lockstep unit test,
  which received `agreement = false` where it accepted only `[null, true]`. The
  two VMs therefore disagree even on the shipped `vault-alpha` grid at
  `maxSteps = 500`, so the headline "differential JS↔Zig C-ABI lockstep over
  1,000 random grids" guarantee does not currently hold. Both failures are
  **pre-existing, not introduced by this release** — they were masked purely by
  step ordering, and the `S9` bench rows are marked
  `zigNotAvailableInSandbox:true` because the authoring sandbox has no Zig
  toolchain, so the comparison short-circuits to `null` there. Candidate root
  causes identified by source review (deliberately unverified and unfixed here,
  since no Zig-capable environment is available): the Zig stack is a fixed
  `[512]i64` returning `.out_of_memory` on overflow whereas the JS stack is an
  unbounded array; Zig arithmetic wraps on `i64` (`+%`, `-%`) while JS uses
  IEEE-754 doubles with no wrapping, so any intermediate beyond 2^53 diverges;
  and `/` on `minInt(i64)` by `-1` yields `maxInt(i64)` in Zig but
  `9223372036854775808` in JS. Stack *underflow* (`popStack` returning `0`), `%`
  on `minInt/-1`, and both output opcodes (`.` as `"{d} "`, `,` as
  `@mod(v,256)`) do match. Tracked as a critical `v0.5.0` item.
* The Nickel L2 gate, the Idris2 `%default total` ABI gate, the native `.so`, and
  `zigBenchNsPerOp` still cannot be exercised in the authoring sandbox: `zig`,
  `nickel`, and `idris2` are all uninstalled and `ziglang.org` is unreachable, so
  `native-oracle.js` reports `available:false` locally. The Idris2 CI step also
  has no viable provisioning source and an independently broken module path — both
  recorded as `v0.5.0` follow-ups.
